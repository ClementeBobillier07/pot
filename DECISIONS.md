# Decisions

1. The prompt supersedes the document's Tauri/Rust proposal. Swift Package Manager organizes a portable PotCore and a macOS 14+ PotApp using system frameworks and SQLite.
2. No macOS host is available in this task. Install an official Swift Linux toolchain for genuine core compilation/tests; never represent these as an AppKit build.
3. Account APIs may report public identity, but legacy JSONL without identity belongs to a provider-local unattributed profile. Do not bind history to the account currently signed in.
4. System SQLite has no third-party package dependency. Sources/cursors/usage/plants persist in a private Application Support folder.
5. Landing is Next.js/TypeScript, local only, no analytics enabled and no public download button claiming an artifact exists.
6. Product source licensing remains owner-reserved pending the creator's choice; notices enumerate dependencies rather than assuming permission to publish under an open-source license.
7. App status commands are bounded subprocesses, not auth implementations. Public Codex account/read is an explicit action inside Connected agents, uses refreshToken:false and times out safely. Default detection uses local status. Vendor subprocess behavior is documented separately from Pot's lack of network code.
8. Calendar statistics use the Mac's current timezone. Energy uses anchored UTC day budgets, a 45-day journal and monotonic persisted high-water time, so timezone changes and repeated imports cannot replenish old budgets. Calibration is elapsed 72h, independent of calendar midnights.
9. Plant biology catches up in at most 45 days of hourly steps and ages older absences analytically. The reserve is capped and distant usage cannot produce instant unlimited maturity. Offline clock manipulation cannot be perfectly authenticated without a trusted time source; the garden favors conservative high-water behavior.
10. Logs without reliable identity stay unattributed. A detected public account can have a separate plant, without claiming it owns past local usage. Account email is optional; aliases and provider-local identity are supported.
11. The app refreshes through debounced recursive FSEvents and a 60-second fallback on a utility queue. Statistics/engine queries are restricted to 45 days rather than decoding lifetime history each minute.
12. ~~Unsupported compressed Zstandard archives report partial coverage.~~ Superseded by 15.
13. Two provider families share a persistent graph renderer. Straight vector branch segments align with the engine's attachment geometry; leaves and flowers interpolate individually. Rendering sleeps when idle and movement stops after a short pulse.
14. Installers use `Pot-<version>-macOS-<arch>.dmg`; local unsigned/ad-hoc development variants have `-local` and are excluded by the public counter. No release, analytics, website or schedule has been published/activated.

15. (macOS, 2026-11-25) Real Codex history is 97 % `.jsonl.zst` (101 of 104 rollouts) and Apple's Compression framework has no Zstandard. Pot vendors the official zstd 1.5.7 single-file **decoder** as a C target (BSD), statically compiled. Archives are immutable: decoded once (≤4 GiB output, default 128 MiB window limit), committed atomically, skipped while inode/size/mtime are unchanged.
16. Only usage-bearing records matter. Codex writes `"type"` within the first ~90 bytes, so records whose type is not session_meta/turn_context/token_usage_record/token_count/thread_settings_applied are skipped without buffering (real tool outputs reach 17 MiB). Claude records are parsed only when they carry `"type":"assistant"`. An oversized or malformed record is "incomplete" only if it is usage-bearing; otherwise it is ignored. The previous rule marked real files partial forever and froze plant health.
17. Codex `session_meta.creator_account_id` is explicit per-session evidence: events are attributed to a pseudonymous `codex:account:<hash>` profile. Claude Code logs carry no account, so Claude history stays in the unattributed local profile.
18. The signed-in account reported by `claude auth status` / Codex app-server no longer creates a plant. Such a plant could never receive events (no per-event identity) and stayed empty. Login identity is display-only.
19. During calibration (fewer than 7 observed active days) the personal reference follows the observed median directly. The ±15 %/day limit applies afterwards. With a 100k-token prior and real usage of ~10^8 tokens/day, the limit credited maximum energy every day for over a month.
20. The app uses a pure AppKit entry point. SwiftUI's placeholder `Settings { EmptyView() }` scene opened an empty "Pot Settings" window at launch on macOS. A minimal main menu restores standard key equivalents.
21. File-event scans are coalesced to at most one every ~4 s; a first import keeps resuming bounded passes for up to 8 s per scan and immediately schedules another until history is imported (≈10 s for 2.3 GB here, instead of one 64 MiB pass per minute).

The GitHub counter stays as the public total but includes the owner's tests and bots; Analytics answers how many people, from where and from which referrer. Nobody is identified. Supersedes decision 5's "no analytics".
31. (2026-11-27, owner) Pot updates itself with Sparkle 2.10.1 (MIT), superseding the "no network client" rule and the browser-only "Check for updates" of the first release. Settings → Updates → "Update Pot automatically" (on by default) checks `agentpots.com/appcast.xml` once a day, downloads in the background and installs as soon as Pot's window is closed, relaunching without a prompt. Off: Pot never checks on its own and Settings shows "Check for updates…" (also in the menu bar menu). Updates must carry an EdDSA signature from the key in the owner's login keychain (account `com.agentpots.pot`; only the public key is in Info.plist) and the same Developer ID team. System profiling is off. `scripts/appcast.sh` writes the appcast; publishing it is the release step. v0.1.0 has no updater, so its users install v0.1.1 by hand once.
30. (2026-11-27, owner) Pot's source is released under the MIT License (`LICENSE`), superseding decision 6. Third-party components keep their own licenses (THIRD_PARTY_NOTICES.md). The signed v0.1.0 binary predates this decision and still carries the old copyright string; builds from now on say "MIT License".
29. (2026-11-26, owner) Plant variants stay a mystery everywhere: the website shows no variants or odds, and the app never names a variant (status line shows only the growth or thirst state). A copihue reveals itself through its stake and bells.
28. (2026-11-26, owner) Window and garden grid give every plant a fixed stage (the whole canvas, pot resting on the bottom) so the composition never changes as it grows; statistics sit at the bottom. The chart shows calendar weeks (first weekday from the locale, Monday in Chile) with today highlighted, future days as faint slots, and arrows for up to five previous weeks. The main window opens on the active Space, including over full-screen apps.

26. (2026-11-26, owner) Plants follow the owner's botanical references: four variants chosen by seed (01 40 %, 02 35 %, 03 24 %, copihue 1 %), steady growth to a full plant after 90 reference days, drawn by `PlantFormBuilder` from seed + growth + health. Wilting follows half the reference timeline (1.5 / 3.5 / 7 / 15 days) after one idle day; recovery shows fresh leaves first and takes ≈ 5–6 days of typical use from dry (+0.15 health per day of use). Engine 3 re-grows older plants from birth. See docs/ENGINE.md.
25. (2026-11-26, owner) Growth engine 2 replaces personal calibration (decisions 8, 9 and 19) with one global rhythm: daily energy = log2(1 + work units ÷ 10 M), capped at 3, where work units weight cache reads ×0.1 and output ×5. Growing is harder (organs cost energy) and wilting is faster: unchanged on the first idle day, −0.18 per idle day afterwards, floor 0.15, recovery ≈ 3 days of use. "Pause the garden" (3c) and plant renaming were removed: a trip just wilts the plant. Older plants re-grow from birth with the new rules. See docs/ENGINE.md.

Desktop arrows were removed; switching plants happens in the app window. The hover zone is the plant's bounds plus the button, so the rest of the transparent panel keeps passing clicks through.
22. Review fixes (2026-11-25): the per-pass file cap counts only files that need reading (a large unchanged history could otherwise stall imports and loop rescans forever); immediate rescans require progress; archives count decoded bytes against the pass budget; relevant records may reach 16 MiB and an oversized Claude record is still recognised by its trailing `"type":"assistant"`; Codex keeps records announcing `service_tier`/`fast_mode`; usage before a resume (same day included) is never credited; "All" combines a cached pre-window summary with the live 45-day window on every scan.
